# AgentShip — Coding Agent Guide

This document is for coding agents (Claude Code, Cursor, Copilot, etc.) scaffolding new AgentShip projects. It describes the exact CLI sequence, the generated file shapes, and the key configuration options.

---

## Scaffolding a new project

```bash
pip install agentship          # or: pip install -e . (from this repo)

agentship init my-project      # creates my-project/ with agentship.toml, agents/, .env
cd my-project

agentship new-agent triage     # creates agents/triage/agent.py + agent.yaml + __skills__/
agentship serve                # discovers agents and starts FastAPI on :7001
```

`POST /agents/triage/chat` is available immediately — no manual registration.

## Generated files

### `agents/<name>/agent.py`

```python
from agentship import Agent

class TriageAgent(Agent):
    pass
```

The class name is PascalCase of the agent name + "Agent". No `__init__` required. The `Agent` base class auto-discovers `agent.yaml` from the same directory.

To customize behaviour, override `before_message`:

```python
class TriageAgent(Agent):
    async def before_message(self, message: str, ctx: dict) -> str:
        # ctx contains user_id, session_id
        return message.strip()
```

### `agents/<name>/agent.yaml`

```yaml
agent_name: triage
engine: langgraph           # only supported engine in this release
model: openai/gpt-4o-mini  # LiteLLM format: provider/model
temperature: 0.4

system_prompt: |
  You are a helpful triage assistant.

memory:
  backend: memory           # memory (default) | postgres
  # url: "${AGENTSHIP_DATABASE_URL}"

observability:
  backend: none             # none (default) | langfuse

mcp:
  servers: []               # See MCP section below
```

## Session persistence

For in-memory sessions (dev/demo):
```yaml
memory:
  backend: memory
```

For Postgres-backed sessions:
```yaml
memory:
  backend: postgres
  url: "${AGENTSHIP_DATABASE_URL}"
```

Set `AGENTSHIP_DATABASE_URL=postgresql://user:pass@localhost:5432/agentship` in `.env`.

## Domain knowledge (`__skills__/`)

Any `.md` files in `agents/<name>/__skills__/` are automatically loaded into the system prompt — no code changes needed.

```
agents/triage/__skills__/
├── intake-protocol.md      # loaded automatically
└── escalation-rules.md     # loaded automatically
```

Delete `example.md` (generated by `agentship new-agent`) and replace with real domain knowledge.

## MCP tool servers (STDIO)

```yaml
mcp:
  servers:
    - name: filesystem
      transport: stdio
      command: ["npx", "-y", "@modelcontextprotocol/server-filesystem", "/tmp"]
```

Tool schemas are auto-discovered on server startup and injected into the system prompt. The agent can call tools without any additional code.

## Observability (Langfuse)

```yaml
observability:
  backend: langfuse
```

Set in `.env`:
```
LANGFUSE_PUBLIC_KEY=pk-lf-...
LANGFUSE_SECRET_KEY=sk-lf-...
LANGFUSE_HOST=https://cloud.langfuse.com  # optional, defaults to cloud
```

Each chat turn emits one OTEL span; each tool call emits a child span. Traces appear in the Langfuse project dashboard.

## Chat API

```bash
curl -X POST http://localhost:7001/agents/triage/chat \
  -H "Content-Type: application/json" \
  -d '{"message": "I need help", "user_id": "u123", "session_id": "s1"}'
```

Response:
```json
{"agent": "triage", "response": "Hello! How can I assist you today?"}
```

Session state is persisted by `(user_id, session_id)` pair.

## Multiple agents

Run `agentship new-agent <name>` multiple times — each agent gets its own route:

```
POST /agents/triage/chat
POST /agents/billing/chat
POST /agents/escalation/chat
```
